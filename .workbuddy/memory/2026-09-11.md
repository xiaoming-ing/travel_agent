## 待修问题（已向用户给出分级）

P0：
1. weather.py / attraction.py / hotel.py 共 5 处 `requests.get`（同步），跑在线程池里；单 worker + 4~6 次串行 10s 超时调用，并发下线程池即瓶颈，且无连接复用。应换 httpx.AsyncClient。
2. core/security.py:6 `JWT_SECRET` 默认 "dev-secret-change-me"，生产未配置即可被伪造 token。应启动时强校验。
3. `require_quota`(deps.py) 与 `add_usage`(quota_store) 是 check-then-act 分离，TOCTOU 并发超额（注意：UPDATE token_used = token_used + ? 本身是原子的，问题在检查与扣减分离）。

P1：
4. 缺 TripPlan 业务校验层（roadmap 阶段二，无 plan_validator.py）——景点名/日期/预算全靠 prompt 约束，无代码保证，是面试最易被击穿的点。
5. 缺评测集与指标（阶段六）——无法量化成功率。
6. 路线规划完全交给 LLM（阶段四）——缺 haversine 聚类 + 最近邻等确定性算法。
7. RAG 全量拉取 chunk 到内存算矩阵（store.fetch_city_chunks），规模一涨即崩；无 chunk metadata 与来源引用。

P2：
8. 缺工作流级集成测试与外部失败分支测试（test_workflow.py 仅 2 个 test）。
9. 无 .github CI、无 Dockerfile；前端 package.json 只有 dev/build/preview，无 lint / vue-tsc typecheck。
10. 所有 DB 操作每次 `aiosqlite.connect` 新开连接，无连接复用，也未设 WAL。
11. 前端 types/index.ts 与后端 Pydantic schema 手工同步，存在 drift 风险。
12. agents/tools.py `search_attractions(preferences: list[str] = [])` 可变默认参数（反模式）。
13. RAG 维度写死 512，换模型会静默降级为"检索无结果"而非报错。

建议优先级：阶段二（业务校验）> 阶段六（评测）> 阶段四（路线优化）> P0 三项。P0 三项改动量小、收益最直接，建议最先做。
