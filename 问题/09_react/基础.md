React运行规律
状态发生变化-函数重新执行-计算新的页面布局-react更新Dom-副作用函数执行

副作用函数
- 修改外部数据,改变全局对象，修改写入的参数对象
- 与外部系统交互，网络请求，读写数据库，操作dom
- 输出到外部，console.log,发送日志，播放声音
副作用函数=做了“本职工作”之外的事的函数。在React中，渲染UI是本职工作，除此之外的操作（请求数据，订阅事件（当某事发生的时候，记得通知我并执行这个回调，事件监听，websocket,事件总线），操作dom）都是副作用，需要用useEffect妥善处理

React Hooks(钩子):让函数组件拥有状态，生命周期，上下文，性能优化等能力等一组函数

### 组件重新渲染是什么
``` 
function Counter(){
    [count,setCount] = useState(0)
    
    return (
        <button onClick={()=>setCount(count+1)}>
        {count}
        </button>
    )
}
```
点击按钮后，setCout更新状态，Counter()重新执行，React得到新的JSX（本质上就是新的虚拟dom），React通过diff比较新和旧的JSX,只更新实际发生变化的DOM
“重新渲染”不等于“整个页面DOM被重新创建”，而是组件函数重新执行，然后React按差异更新DOM

### 01，useState:保存组件状态
const [count,setCount] = useEffect(0)
count:当前状态
setCount:更新状态的方法

### 02. useEffect:与外部系统同步
1.干什么的？
用来处理“渲染完成后，需要和组件外部发生联系”的事情，例如：
发送网络请求，添加事件监听，创建定时器，操作浏览器API，链接websocket
useEffect不是简单的监听变量，更准确的说是：组件应该如何根据当前数据，与外部系统保持同步
```
2.依赖变化后，发生了什么？
useEffect(()=>{
    console.log("建立同步",count)

    return () => {
        console.log("清理同步",count)
    }
},[count])
```
如果count从1变成2，组件使用count=2重新渲染 -- React更新界面 -- 执行上一次Effect的清理函数（清理count=1）--执行新的Effect(使用count=2)
3.三种依赖数组
不写依赖数组，每次选然后执行
useEffect(()=>{
    cosnole.log('3333')
})
空数组，挂载后执行
useEffect(()=>{
    console.log('3333')
},[])
指定依赖，依赖变化后执行
useEffect(() => {
    fetchUser(userId)
}, [userId])

### 03.useMemo:缓存计算结果
const visibleUsers = useMemo(()=>{
    return users.filter(user=>user.name.includes(keyword))
},[users,keyword])
首次渲染时，React执行计算函数并保存结果。组件重新渲染，users和keyword都没变，返回缓存的结果。任意依赖值发生变化重新执行计算函数，保存新结果

### 04.useCallback:缓存函数引用
const handleDelete = useCallback(()=>{
    deleteUser(userId)
},[userId])
它缓存的是函数本身：
- userId没变：返回上一次的函数
- userId变化：返回一个新函数
不用useCallback,每次函数重新渲染的话，这个方法都是新的对象
